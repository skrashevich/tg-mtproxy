# MTProxy Telegram Bot

Бот для продажи доступа к MTProto proxy для Telegram.
Оплата через Telegram Stars — без регистраций, ИП, и платёжных систем.

## Что делает

- Пользователь пишет боту → выбирает тариф → оплачивает Stars → получает ссылку на прокси
- Поддержка нескольких серверов (локальных и удалённых через SSH)
- Автоматический выбор наименее загруженного сервера
- Мониторит RAM, подключения, истёкшие подписки на всех серверах
- Автонастройка удалённых серверов (установка Docker, MTProxy)
- Алертит админа при перегрузке

## Архитектура

```
┌─────────────┐     ┌──────────────┐     ┌──────────────────────┐
│  Telegram    │────▸│  Node.js Bot  │────▸│  Local: Docker       │
│  Users       │◂────│  (telegraf)   │     │  MTProxy             │
│              │     │  SQLite DB    │     └──────────────────────┘
└─────────────┘     └──────────────┘
                         │    │           ┌──────────────────────┐
                         │    └──── SSH ─▸│  Remote: Docker      │
                         │                │  MTProxy             │
                         ▼                └──────────────────────┘
                    Cron Jobs:
                    - Проверка expire (30 мин)
                    - Мониторинг RAM (5 мин)
                    - Перезапуск proxy (1/день)
```

**Мультисерверная архитектура:**
- Каждый сервер — один Docker-контейнер MTProxy на одном порту
- Локальные серверы управляются через Docker напрямую
- Удалённые серверы управляются через SSH + Docker
- Каждому юзеру — уникальный secret, привязка к конкретному серверу
- При добавлении/удалении юзера — рестарт только затронутого сервера (~2 сек)

## Требования

- VDS: Ubuntu 22+, 1 ГБ RAM, 1 vCPU (для каждого сервера)
- Docker (устанавливается автоматически через `/setup_server`)
- Node.js 18+ (только на основном сервере, где запущен бот)
- Открытый порт 443 (на каждом сервере)

## Мультисерверная конфигурация

Серверы настраиваются через `data/servers.json`. Если файл не существует, он автоматически создаётся из `.env` (обратная совместимость).

Пример (`servers.example.json`):
```json
[
  {
    "name": "local",
    "type": "local",
    "host": "123.45.67.89",
    "port": 443,
    "container_name": "mtproxy",
    "max_users": 50
  },
  {
    "name": "eu-1",
    "type": "remote",
    "host": "98.76.54.32",
    "port": 443,
    "container_name": "mtproxy",
    "ssh_host": "root@98.76.54.32",
    "ssh_port": 22,
    "ssh_key_path": "/path/to/key",
    "max_users": 50
  }
]
```

### Добавление удалённого сервера

1. Добавить сервер в `data/servers.json`
2. В боте: `/reload_servers` — загрузить конфигурацию
3. `/ssh_key` — получить публичный SSH-ключ бота
4. `/deploy_key <id> <github_user>` — установить ключ бота + ключи с GitHub на сервер
5. `/setup_server <id>` — автоматически установит Docker и запустит MTProxy
6. `/enable_server <id>` — сервер начнёт принимать пользователей

Бот автоматически распределяет пользователей по наименее загруженным серверам.

## Оплата через Telegram Stars

**Как это работает:**
1. Пользователь нажимает "Купить" в боте
2. Telegram показывает нативную форму оплаты Stars
3. Юзер платит Stars (которые купил через Apple Pay / Google Pay / @PremiumBot)
4. Бот получает подтверждение от Telegram автоматически
5. Ссылка на прокси выдаётся моментально

**Как вывести деньги:**
- Stars → Toncoin через Fragment (fragment.com)
- Toncoin → рубли через любую крипто-биржу

**Для этого НЕ нужно:**
- Регистрироваться как ИП/самозанятый (для старта)
- Подключать платёжные системы
- Получать provider_token — для Stars он пустой

## Тарифы

| Тариф | Stars | Дни | ~Рублей |
|-------|-------|-----|---------|
| ⚡ 1 день | 8 | 1 | ~15 |
| 🔵 7 дней | 25 | 7 | ~50 |
| 🟣 30 дней | 50 | 30 | ~100 |

1 Star ≈ 1.8-2.4 руб при покупке через @PremiumBot.

Изменить тарифы: `src/tariffs.ts`

Бесплатный триал настраивается через `.env`:
- `TRIAL_DAYS` — длительность в днях (`0` = выключен)
- `TRIAL_MAX_CONNECTIONS` — лимит устройств в триале
- `TRIAL_NOTIFY_ADMIN` — уведомления админу о выдаче триала (`1`/`0`)

## FAQ

**Q: Почему один контейнер на сервер, а не отдельный на юзера?**
На 1 ГБ RAM каждый Docker-контейнер ест ~30-50 МБ. При 50 юзерах это 1.5-2.5 ГБ — не влезет.
Один контейнер с множественными секретами ест ~30-50 МБ на всех.

**Q: Что будет при перезапуске контейнера?**
Юзеры переподключатся автоматически через ~5-10 сек. Telegram клиент это умеет.

**Q: А если юзер шарит ссылку?**
MTProxy не различает юзеров по секрету на уровне подключений.
Это ограничение протокола — полностью предотвратить шаринг нельзя.
Но: бесплатный триал + низкая цена делают шаринг бессмысленным.

**Q: Масштабирование?**
Добавь удалённые серверы через `data/servers.json`. Бот автоматически распределяет нагрузку.
Каждый сервер на 1 ГБ RAM держит ~50 юзеров. Два сервера — 100, три — 150 и т.д.

**Q: Как добавить новый сервер без SSH-ключа?**
1. `/ssh_key` — покажет публичный ключ бота
2. Добавь его вручную на сервер в `~/.ssh/authorized_keys`
3. Или `/deploy_key <id> <github_user>` — установит ключ автоматически (если SSH уже работает)
4. `/setup_server <id>` — всё остальное автоматически
